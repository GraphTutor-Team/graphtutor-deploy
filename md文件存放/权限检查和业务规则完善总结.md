## 📝 使用示例

### 权限检查

```javascript
import PermissionService, { checkPermission } from '../services/permissionService.js';

const result = await PermissionService.canModifyBank(user, bank);
checkPermission(result); // 如果失败会抛出ForbiddenError
```

### 业务规则验证

```javascript
import BusinessRules from '../services/businessRules.js';

BusinessRules.validateQuestionOptions(options, 2, 10);
BusinessRules.validateAnswerIndex(answerIndex, options);
BusinessRules.validateDifficulty(difficulty, 1, 5);
```

### 中间件使用

```javascript
import { checkModifyBank } from '../middleware/checkPermission.js';

router.put('/banks/:id',
  requireAuth,
  checkModifyBank, // 自动检查权限并挂载req.bank
  handler
);
```

## 🔧 技术细节

### 权限检查流程

1. **加载资源**: 从数据库加载资源
2. **检查权限**: 使用PermissionService检查权限
3. **返回结果**: 返回PermissionResult对象
4. **处理结果**: 使用checkPermission或hasPermission处理

### 业务规则验证流程

1. **参数验证**: 检查参数类型和格式
2. **业务规则验证**: 检查是否符合业务规则
3. **抛出错误**: 如果验证失败，抛出相应的错误

### 错误类型

- `ForbiddenError` - 权限不足
- `NotFoundError` - 资源不存在
- `BadRequestError` - 请求参数错误
- `ConflictError` - 数据冲突

## 🚀 权限规则

### 题库权限

- **查看**: 管理员 > 官方题库 > 小组题库 > 个人公开题库 > 个人私有题库
- **修改**: 管理员 > 官方题库（仅管理员）> 小组题库（群组老师）> 个人题库（创建者/管理者）
- **删除**: 管理员 > 官方题库（仅管理员）> 小组题库（群组老师）> 个人题库（仅创建者，无其他管理者）

### 题目权限

- **修改**: 管理员 > 创建者 > 题库关联权限

### 笔记和讨论权限

- **查看**: 管理员 > 公开内容 > 私有内容（仅创建者）
- **修改**: 管理员 > 创建者

## ⚠️ 注意事项

### 1. 权限检查顺序

- 先检查用户是否认证
- 再检查资源是否存在
- 最后检查权限

### 2. 业务规则验证

- 在创建/更新数据前进行验证
- 验证失败会抛出相应的错误
- 使用try-catch捕获错误

### 3. 性能考虑

- 权限检查会查询数据库，注意缓存
- 业务规则验证是同步的，注意性能影响
