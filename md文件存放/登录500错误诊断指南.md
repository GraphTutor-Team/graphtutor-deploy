# 登录500错误诊断指南

**创建时间**: 2026-01-20

## 🔍 问题描述

登录接口 `/api/auth/login` 返回 500 错误。

## ✅ 已修复的问题

### 1. 错误处理中间件导入
- **问题**: `app.js` 中使用了 `handleError` 但未导入
- **修复**: 已添加 `import { handleError } from "./utils/errorHandler.js";`

### 2. 认证中间件错误处理
- **问题**: `requireAuth` 中间件中数据库查询错误可能导致500
- **修复**: 已添加数据库查询错误处理，使用 payload 作为兜底

### 3. 登录路由错误处理
- **问题**: 错误处理不够详细
- **修复**: 已添加详细的错误处理和日志

## 🔧 诊断步骤

### 步骤1: 检查服务器控制台错误日志

查看服务器控制台（nodemon输出），查找以下错误：

1. **数据库连接错误**
   ```
   MongoDB connection failed
   ```
   - **解决方案**: 确保MongoDB服务正在运行
   - **检查**: `mongod --version` 或检查MongoDB服务状态

2. **JWT_SECRET错误**
   ```
   JWT_SECRET is undefined
   ```
   - **解决方案**: 检查 `.env` 文件中是否有 `JWT_SECRET`
   - **默认值**: 如果未设置，会使用 `"dev-secret"`

3. **模块导入错误**
   ```
   Cannot find module
   ```
   - **解决方案**: 运行 `npm install` 安装依赖

### 步骤2: 检查数据库连接

```bash
# 检查MongoDB是否运行
# Windows
net start MongoDB

# 或检查端口
netstat -ano | findstr :27017
```

### 步骤3: 检查环境变量

确保 `.env` 文件存在且包含：

```env
MONGODB_URI=mongodb://127.0.0.1:27017/graphtutor
JWT_SECRET=your-secret-key-here
PORT=5000
```

### 步骤4: 测试数据库连接

运行测试脚本：

```bash
cd server
node src/routes/auth-debug.js
```

### 步骤5: 检查中间件顺序

确保 `app.js` 中的中间件顺序正确：

1. 安全头
2. CORS
3. 请求体解析
4. 响应时间监控
5. 日志
6. **限流器**（在路由之前）
7. 路由
8. **错误处理**（在404之前）

## 🐛 常见问题

### 问题1: 数据库未连接

**症状**: 所有数据库查询都失败

**解决方案**:
1. 启动MongoDB服务
2. 检查 `MONGODB_URI` 是否正确
3. 检查防火墙设置

### 问题2: 限流器导致429错误

**症状**: 返回429 Too Many Requests

**解决方案**:
- 等待15分钟后重试
- 或临时禁用限流器进行测试

### 问题3: JWT_SECRET未设置

**症状**: JWT签名失败

**解决方案**:
- 在 `.env` 文件中设置 `JWT_SECRET`
- 或使用默认值（开发环境）

### 问题4: 中间件抛出未捕获错误

**症状**: 500错误但无详细日志

**解决方案**:
- 检查所有中间件是否有错误处理
- 确保 `handleError` 中间件已正确导入和使用
