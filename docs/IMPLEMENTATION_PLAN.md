# GraphTutor 实施计划（分步路线图）

> 基于《PAGES_AND_FEATURES.md》第十四章「产品愿景与中长期规划」拆解的可执行步骤。  
> 每阶段约 3–6 个月，可按资源与优先级调整节奏。

---

## 总览

| 阶段 | 主题 | 目标周期 | 核心产出 |
|------|------|----------|----------|
| **Phase 0** | 基建与 AI 能力准备 | 0–2 月 | AI 接口统一、上下文注入、前端助手壳 |
| **Phase 1** | AI 深度整合（第一波） | 2–5 月 | 全局 AI 伴侣 + 题目 AI 讲解 + 智能出题增强 |
| **Phase 2** | 数据智能与自适应学习 | 5–8 月 | 学习预测、遗忘曲线、难度调整、知识图谱增强 |
| **Phase 3** | 游戏化与社交深化 | 8–11 月 | 技能树、每日挑战、师徒/小组 2.0、成就商城 |
| **Phase 4** | 内容生态与机构版 | 11–14 月 | 付费内容、名师班级、机构后台、Open API |
| **Phase 5** | 多端与国际化 | 14–18 月 | 小程序/App、多语言、多地区内容 |
| **Phase 6** | 创新实验与长期形态 | 18 月+ | AR/VR/语音、学习操作系统形态 |

---

## Phase 0：基建与 AI 能力准备（0–2 月）

**目标**：为后续「AI 学习伴侣」「AI 讲解」等提供统一入口与数据上下文，不急于做完整产品形态。

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 0.1 | **统一 AI 服务层**：封装现有/新增 LLM 调用（OpenAI/国产大模型），统一 prompt 模板、限流、计费埋点 | 无 | 后端 `/api/v3/ai/chat` 或等价接口可用，支持流式与非流式 |
| 0.2 | **上下文注入规范**：定义「当前页面类型、当前题目、当前知识点、近期错题 ID」等上下文结构，供 AI 接口消费 | 0.1 | 文档化 JSON schema，并在 1–2 个页面试点传入 |
| 0.3 | **前端全局悬浮组件**：右下角固定「AI 助手」入口，点击展开对话面板（先仅 UI，可接简单问答或占位文案） | 无 | 任意页可展示悬浮按钮与面板，不阻塞现有路由 |
| 0.4 | **题目详情「AI 讲解」占位**：在题目详情页增加「AI 讲解」按钮，点击可调 0.1 接口并展示返回内容（先用固定 prompt） | 0.1, 0.2 | 题目详情页有按钮，能完成一次讲解请求并展示 |

---

## Phase 1：AI 深度整合（第一波）（2–5 月）

**目标**：用户可随时问 AI、在题目页获得讲解；出题与笔记侧 AI 能力增强。

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 1.1 | **智能问答（学习伴侣）**：悬浮助手接入 0.1，根据 0.2 上下文支持「解题思路」「知识点常考题型」「根据错题推荐 N 道题」等预设/自由问 | Phase 0 | 三种示例问题可得到有用回复；可选：推荐题目带跳转链接 |
| 1.2 | **题目详情 AI 讲解**：优化 prompt，稳定输出「答案依据 + 解题步骤 + 易错点」；支持重新生成/复制 | 0.4 | 讲解质量稳定，可配置模型/温度 |
| 1.3 | **智能出题增强**：在现有 AI 出题基础上，支持「知识点 + 难度」输入，输出题目+答案+解析，并接入题目审核/入库流程 | 现有出题流程 | 管理员/老师可从「知识点+难度」一键生成并审核入库 |
| 1.4 | **笔记自动摘要**：对长笔记调用 AI 生成摘要卡片，在笔记列表/首页展示摘要字段 | 0.1 | 新建/编辑笔记可触发摘要，列表展示摘要 |
| 1.5 | **错题分析报告（MVP）**：按周/月聚合用户错题，调用 AI 生成一段「错题分析 + 复习建议」，通过通知或学习分析页展示 | 0.1, 错题数据 | 用户可在「学习分析」或通知中看到周/月错题报告 |

## Phase 2：数据智能与自适应学习（5–8 月）

**目标**：学习预测、遗忘提醒、动态难度、知识图谱可视化增强。

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 2.1 | **遗忘曲线预警**：基于作答时间与正确率，对知识点估计「遗忘概率」；在首页/复习页提示「建议今日复习」 | Record/错题数据 | 至少一个页面展示「N 天后遗忘概率」及复习入口 |
| 2.2 | **学习效率分析**：按时间段、题型统计正确率与耗时，输出「最佳学习时段/题型」建议 | 学习分析现有数据 | 学习分析页增加「效率分析」模块 |
| 2.3 | **动态难度调整（练习）**：练习模式下，根据近期正确率动态选择下一题难度（需题目有难度标签） | 题目难度、Record | 练习流程中下一题难度随表现变化 |
| 2.4 | **知识图谱热力图**：在图谱节点上展示掌握度、错题人数等，用颜色/数值区分 | 知识图谱、Record | 图谱页可看到节点热度/掌握度 |
| 2.5 | **路径推荐**：「掌握 A、B 的用户常学 C」类推荐，在首页或学习路径页展示 | 2.4、用户行为数据 | 至少一个入口展示「推荐下一步学习」 |
| 2.6 | **考前预测 + 预测卷**：基于错题与掌握度，列出薄弱知识点并生成「预测卷」入口 | 错题、题目池 | 用户可一键生成并开始预测卷练习 |
| 2.7 | **个性化路径生成（MVP）**：用户输入目标（如考试日期），生成「每日学习计划」并与练习/错题打通 | 1.x, 2.x | 输入目标后可看到每日计划及完成状态 |

## Phase 3：游戏化与社交深化（8–11 月）

**目标**：技能树、每日挑战、联赛雏形、师徒/小组 2.0、成就商城。

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 3.1 | **学科技能树**：按学科建技能树，节点对应知识点；根据作答记录点亮节点 | 学科/知识点、Record | 每个学科一棵树，节点可点亮 |
| 3.2 | **学习角色与等级**：用户有等级/经验值，做题、打卡、完成任务获得经验 | 无 | 个人页展示等级与经验，规则文档化 |
| 3.3 | **每日挑战**：固定 10 题，全站同题，完成后参与当日排名 | 题目池、排名存储 | 每日挑战页可做题并看排名 |
| 3.4 | **学科联赛（月度）**：按月开放某学科联赛，段位（青铜/银/金），按积分或胜场晋级 | 3.2, 3.3 | 联赛页可报名、做题、查段位 |
| 3.5 | **成就商城（虚拟道具）**：成就/积分可兑换「免错题卡」「双倍经验」等虚拟道具并在规则中生效 | 3.2, 成就系统 | 兑换后道具在指定场景生效 |
| 3.6 | **师徒系统**：建立师徒关系、师徒任务、徒弟进步统计；师徒排行榜 | 群组/好友 | 可拜师/收徒，有简单任务与排行 |
| 3.7 | **学习小组 2.0**：小组共享错题本/好题本、小组周报（排名+贡献度）；可选：自习室（仅 UI 或简单语音） | 群组、错题 | 小组有共享题库与周报 |
| 3.8 | **问答社区升级**：悬赏提问（积分）、高赞沉淀为精华、学科专家标识（规则+展示） | 社区现有 | 悬赏流程跑通，精华区与专家标识上线 |

---

## Phase 4：内容生态与机构版（11–14 月）

**目标**：付费题库/笔记、名师班级、机构后台、开放 API。

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 4.1 | **付费题库**：题库可设为付费，支付后解锁；平台抽成与结算规则（可先简化） | 支付/订单（可对接现有或模拟） | 创建付费题库并完成一次购买流程 |
| 4.2 | **精品笔记付费**：笔记可设为「付费可见」，支付后可看 | 4.1 | 笔记设置付费后，未付费用户仅见摘要或提示 |
| 4.3 | **名师班级**：群组升级为「班级」，支持付费加入、作业/批改/答疑（与现有作业、消息打通） | 群组、作业、支付 | 老师可创建付费班级，学生付费加入并使用作业与答疑 |
| 4.4 | **机构后台**：创建机构、多班级、全班/全校数据看板、统一布置作业与考试 | 群组、作业、考试 | 机构管理员可管理班级与查看学情 |
| 4.5 | **教学计划导入**：按教学大纲导入计划，自动生成练习/复习任务（MVP 可为表格导入） | 4.4, 题目/知识点 | 支持导入一份计划并生成任务 |
| 4.6 | **Open API**：认证、限流、核心接口（用户、题目、练习记录、错题）文档化并开放 | 现有 API | 文档 + 示例，至少 3 个核心接口可被第三方调用 |
| 4.7 | **UGC 激励**：创作者流量分成规则、月度大赛与奖金池、创作者标识 | 4.1, 4.2 | 分成规则上线，大赛至少办一届 |

## Phase 5：多端与国际化（14–18 月）

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 5.1 | **小程序**：核心场景（练习、错题、打卡、简单统计）迁移到小程序 | 现有接口 | 小程序可完成练习与看错题 |
| 5.2 | **移动 App**：离线题目包、推送提醒、与现有账号数据同步 | 5.1 或并行 | 支持离线做题与推送 |
| 5.3 | **界面多语言**：中/英（先），语言包与切换入口 | 无 | 关键页面支持中英切换 |
| 5.4 | **题目多语言**：同一题目支持多语言版本，做题时按用户语言选择 | 题目模型、5.3 | 题目有多语言字段并在前端按语言展示 |
| 5.5 | **多地区内容**：对接 1–2 类考试大纲（如四六级/考研），本地化推荐与标签 | 题目/知识点、推荐 | 某类考试有专属标签与推荐 |

## Phase 6：创新实验与长期形态（18 月+）

| 步骤 | 内容 | 依赖 | 验收标准 |
|------|------|------|----------|
| 6.1 | **语音交互**：语音控制（「下一题」「讲解一下」）、可选语音答题（如外语） | Phase 1 讲解、ASR/TTS | 至少语音控制在 1 个页面可用 |
| 6.2 | **AR/VR 实验**：AR 扫码出知识点或 VR 教室 demo（可选合作方） | 无 | 内部或小范围 demo |
| 6.3 | **学习操作系统形态**：首页/工作台全面以「学习中枢」呈现，AI 默认嵌入各环节，数据与内容统一入口 | Phase 1–4 | 产品形态文档 + 核心路径重构 |

---

## 执行建议

1. **每阶段收尾**：输出阶段总结、可演示功能列表、下阶段排期与风险。  
2. **依赖优先**：Phase 0 的 0.1、0.2、0.3 建议优先完成，再并行 1.1 与 1.2。  
3. **可裁剪**：若资源有限，可只做 Phase 0 + Phase 1（1.1–1.3），仍能形成「AI 伴侣 + 讲解 + 出题」的清晰卖点。  
4. **与现有功能对齐**：实施时对照《PAGES_AND_FEATURES.md》前十三章，避免与现有页面/接口冲突，必要时先做小范围重构再扩展。
