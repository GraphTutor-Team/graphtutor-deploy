## 第一幕：开场（30 秒 · 共同）

**谁说**：A 开场，B 接一句分工。

**话术示例**：

> **A**：我们是 GraphTutor 智能学习助手微信小程序，两人一组，与 Web 端共用同一套后端和 MongoDB 数据库。  
> **B**：我负责账号与社交模块；A 负责学习中心。下面从登录开始完整演示一条用户路径。

**可指屏幕**：首页 Hero、底部 5 个 Tab（首页 / 练习 / 计划 / 错题 / 我的）。

---

## 第二幕：登录与账号（1～1.5 分钟 · B 主讲）

| 步骤 | 操作 | 讲解要点 |
|------|------|----------|
| 1 | 未登录时首页点 **「去登录」** | 小程序通过 `utils/api.js` 的 `wx.request` 访问后端，Header 带 `X-Client: miniprogram` |
| 2 | 登录页：邮箱密码 / 微信登录（视你们配置） | 登录成功返回 JWT，存 `wx.setStorageSync('token')` |
| 3 | 若弹出 **完善账号** | B 负责：`needsProfileCompletion` → 绑定邮箱，与 Web 数据对齐 |
| 4 | 登录后进 **「我的」** Tab | 展示头像、昵称、邮箱；菜单分：学习中心 / 学习工具 / 社交 |

**B 一句话技术点**：

> 登录态用 JWT + 本地 storage；`ensureValidAccessToken` 过期会自动 refresh，各页 `onShow` 里检查登录。

**截图对应**：报告图 — 登录页、我的页。

---

## 第三幕：首页与学习入口（30 秒 · A 主讲）

| 步骤 | 操作 | 讲解要点 |
|------|------|----------|
| 1 | 切 **「首页」** Tab | 展示通知、推荐题、今日复习数（与后端 v3 API 同步） |
| 2 | 点 **「开始练习」** 或切 **「练习」** Tab | 进入 A 的学习中心主入口 |

**A 一句话**：

> 首页并行请求推荐、今日复习等接口；失败有兜底，不影响登录和刷题。

---

## 第四幕：练习 → 答题 → 交卷（2～2.5 分钟 · A 主讲 · 核心）

| 步骤 | 操作 | 讲解要点 |
|------|------|----------|
| 1 | **练习 Tab** → **练习模式** 或 setup 页 | 选学科 / 题库 / 题量 |
| 2 | 点 **开始练习** | 调用 `startQuizSession` → 创建会话 |
| 3 | 进入 **答题页** session | 单选/多选/填空；答案先存页面 `data` |
| 4 | 答 1～2 题后 **交卷** | `submitSessionAnswers` + `finishQuizSession` |
| 5 | **结果页** result | 展示得分；错题由后端写入错题本 |

**可选加分（15 秒）**：

- **练习 Tab** → **今日复习** / **错题巩固**（`quiz-launch.js` 一键开练）
- 或 **考试模式**：计时 + 交卷前 `wx.showModal` 确认

**A 技术关键词**：`startQuizSession` → `getQuizSession` → `submitSessionAnswers` → MongoDB 与 Web 同步。

**截图对应**：练习配置、答题页、结果页、错题 Tab。

---

## 第五幕：错题与计划（1.5～2 分钟 · A 主讲）

| 步骤 | 操作 | 讲解要点 |
|------|------|----------|
| 1 | **「错题」** Tab | `getWrongQuestions` 列表；可按掌握度筛选 |
| 2 | 点某题 **再练** 或 **标记掌握** | `launchSingleQuestion` / `markWrongQuestionMastered` |
| 3 | **「计划」** Tab | 今日复习数、学习计划、**打卡** |
| 4 | 点 **打卡** | `checkInStudyPlan`；无计划可 **创建默认计划** |
| 5 | （可选）**复习计划** 页 → 开始今日复习 | `executeReviewPlan` → 跳转答题 |

**A 话术**：

> 学习闭环是：练习交卷 → 错题本 → 复习计划/打卡 → 再练，数据都在同一 MongoDB，Web 端也能看到。

## 第七幕：好友与消息（1.5～2 分钟 · B 主讲）

| 步骤 | 操作 | 讲解要点 |
|------|------|----------|
| 1 | **我的** → **好友管理** | 顶部 **搜索邮箱/昵称** → **加好友** |
| 2 | 若有 **待处理请求** | 接受 / 拒绝 |
| 3 | 好友列表点 **发消息 ›** | 进入聊天页；仅好友可私信 |
| 4 | **我的** → **消息** | 会话列表；可删除会话 |
| 5 | 聊天页发一条文字 | `sendMessage`；消息按时间正序，新消息在底部 |

**B 技术关键词**：`/api/v3/friends/search`、`/api/v3/messages`、软删除会话。

**若无演示好友**：说明已提供 `seed-user-demo.js` 可导入王浩然等演示数据。

| 1 | **我的** → **学习笔记** | 列表 / 详情 / 新建（`createNote`） |
| 2 | **学习社区** | 讨论列表、发帖、回复 |
| 3 | （可选）**排行榜** | 与后端 leaderboard API |

**B 话术**：

## 第九幕：收尾与架构（1 分钟 · 共同）

**A**：

> 学习中心通过 `api.js`、`quiz-launch.js` 对接 REST API；4G 服务器更新用 `deploy-server-only.sh` 只替换后端，避免 Docker 全量 build 卡死。

**B**：

> 账号与社交走同一 `BASE_URL`；小程序用 `X-Client: miniprogram` 区分客户端，HTTP 部署注意 `COOKIE_SECURE` 与 CSRF。

**共同一句**：

> 项目是 **微信小程序 + Node 后端 + MongoDB**，两人分工 A 学、B 社，数据与 Web 互通。演示视频与报告、评分表已按分工分别提交。

## 翻车备用方案

| 情况 | 处理 |
|------|------|
| 网络 502 / 超时 | 说「推荐接口已做兜底」；改演示练习/错题/好友（不依赖首页推荐） |
| 登录失败 | 用已登录缓存；或播放预录视频 |
| 好友为空 | 口头说明 seed 脚本；或现场搜另一个账号加好友 |
| 服务器挂了 | 播放演示视频 + 展示代码结构与报告架构图 |
