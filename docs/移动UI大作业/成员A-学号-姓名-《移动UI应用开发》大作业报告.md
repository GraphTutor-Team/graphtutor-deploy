## 一、需求分析与方案（小组共同）

### 1.1 项目背景

GraphTutor 是面向高校学生的智能学习平台。Web 端已有题库、错题本、学习计划等功能；本小组在 **微信小程序** 实现移动端核心流程，与后端 API 对接，实现账号互通与数据同步。

> **【截图位置：图1】** 小程序首页（登录后）。

### 1.2 可行性分析

- **技术**：微信小程序 + REST API，课程知识可覆盖  
- **经济**：开发者工具与现有服务器，无额外成本  
- **操作**：5 Tab 导航，3 步内可开始刷题  

### 1.3 功能模块（小组划分）

| 模块 | 负责人 | 主要内容 |
|------|--------|----------|
| 账号与社交 | 成员 B | 登录、注册、我的、好友、消息、笔记、社区 |
| **学习中心** | **成员 A（本人）** | **练习、考试、答题、错题、计划、打卡、复习、统计** |
| 公共部分 | 共同 | app.json、config、联调、测试、文档、视频 |

> **【截图位置：图2】** 功能模块结构图（标注 A/B 分工颜色）。→ 见 **`大作业配图-架构与流程图.md`** **图A-1**。

### 1.4 业务流程

登录 → 首页 → **练习/交卷/错题/计划/打卡**（A）→ 好友/笔记（B）。

## 三、项目实现（成员 A 负责部分）

### 3.1 练习与考试

1. 选题库 → `startQuizSession` → 跳转 session  
2. 本地记录答案，交卷 `submitSessionAnswers`（失败则逐条降级）  
3. 跳转 result 展示得分；错题由后端写入错题本  

> **【截图位置：图7】** 练习配置页  
> **【截图位置：图8】** 答题页  
> **【截图位置：图9】** 结果页  
> **【截图位置：图10】** session.js 交卷逻辑代码截图  

### 3.2 错题与复习

1. wrong 页 Tab 筛选掌握度，调用 `getWrongQuestions`  
2. `launchWrongPractice` / `launchReviewPlan` 拉题 ID 开练  
3. 修复 `extractQuestionId`，优先使用 `questionId` 字段  

> **【截图位置：图11】** 错题 Tab  
> **【截图位置：图12】** 复习计划 + 开始今日复习  
> **【截图位置：图13】** launchReviewPlan 代码截图  

### 3.3 计划与打卡

1. plan 页展示今日复习数、进行中计划、打卡入口  
2. checkin 页调用 `checkInStudyPlan`；无计划时自动创建默认计划  
3. 联调修复服务端打卡路由 bug  

> **【截图位置：图14】** 计划 Tab  
> **【截图位置：图15】** 打卡页 + 成功提示  
> **【截图位置：图16】** checkin.js 中 doCheckIn 代码截图  

### 3.4 与成员 B 协作点

- 依赖 B 完成的 **登录态**（Token）才能请求练习/错题接口  
- 「我的页」中练习/计划入口由 B 菜单跳转至 A 页面  
- 联调：A 提供答题流程，B 验证登录后能否正常进入 Tab
